# Native Orca traversal

Actual Orca 46.1 ran with AT-SPI in an isolated Openbox/X11 desktop session on
Ubuntu 24.04. The application used the real GTK accessibility backend, not GTK's
test backend. A private D-Bus fixture supplied explicitly simulated devices and
transfers; no protocol listener or physical radio was started.

The first traversal exposed a production bug: a device's custom box child did
not provide GtkToggleButton with an accessible name. Orca spoke only “toggle
button, not pressed”. Device cards now expose their displayed device name as the
accessible label and protocol list as the description. Native toggle state
continues to expose whether the device is selected.

After the fix, the repeatable probe passed:

- Tab reached named Choose Files, Manage Devices, Refresh and device controls.
  Space selected the device, and AT-SPI reported the pressed state.
- The real Orca speech-generation log contained the displayed device name and
  the focused control labels. The protocol description exposed LocalSend and
  Quick Share.
- The named progress bar exposed 0.43 within its numeric range for the 43% fixture.
- The incoming review control was reachable by Tab; the probe did not accept
  an incoming transfer or bypass its confirmation.
- Ctrl+1–4 opened all four views, including the named settings-search control.
- Keyboard help was a native accessible dialog; Escape dismissed it.

Run after building the application:

```sh
sh app/linuxdrop/tests/run-orca-smoke.sh /path/to/linuxdrop /path/to/output
```

Dependencies: Orca, python3-pyatspi, python3-gi, Openbox, Xvfb, xauth, xdotool,
dbus-x11, and the German UTF-8 locale. The wrapper creates separate home, runtime,
configuration, data and cache directories and excludes LinuxDrop daemon activation
from its private bus. Only child processes created by the probe are terminated.
The scenario is also wired into CI against the built DEB, after installation.
App all-target Clippy passed locally; the new remote CI job is not yet verified.

This is real screen-reader speech generation and keyboard traversal, with
AT-SPI value/state inspection. It is not an assessment of physical audio quality,
Braille hardware, every optional settings field, or GNOME Shell's accessibility
tree. Shell screen-reader traversal remains separate from its native keyboard
and focus tests.
