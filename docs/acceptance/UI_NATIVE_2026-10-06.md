# Native UI acceptance — 2026-10-06

Final interaction update: a dedicated top-panel LinuxDrop icon now replaces the
always-visible compact bubble. The bubble starts fully hidden and opens only on
click/keyboard activation. Incoming/progress updates do not open it. One isolated
GNOME 46 headless smoke session verified hidden startup, panel click opening,
the **Drop files** action mapping the real GTK target, outside-click dismissal,
and Escape dismissal. JS syntax and strict GSettings schema validation passed.
The running user desktop was not reloaded. [Closed](ui/panel-closed.png),
[opened](ui/panel-open.png). The description label was then changed to wrap
instead of ellipsizing. The following earlier captures document the app and
native file-transfer integration; their always-visible compact bubble is
superseded by this final interaction.

Environment: Ubuntu 24.04 in WSL2, GTK 4.14.5, libadwaita 1.5, GNOME Shell 46.2,
Nautilus 46, native Wayland clients. The isolated review compositor used a
1440×900 virtual monitor at 100%, software rendering, and a dedicated runtime
directory/session bus. These captures establish native Linux rendering and
interaction; they do **not** establish that the outer Windows/WSLg presentation
is correct. The installed visible demo is tested separately.

Screenshots were captured during the same implementation review. Later small
polish changes increased compact notch width to 240px with a shorter device
count, localized transfer/backend labels, removed the extra Close button from an
active link offer (dismiss now also stops it), and shortened unavailable
Bluetooth diagnostics into a tooltip. The latest hardware capture shows the
full-width compact bubble; earlier captures retain the previous compact label.
No screenshot contains a fabricated discovered device. The incoming peer is
explicitly named as a loopback UI test fixture.

Reproduction helpers live in `app/linuxdrop/tests/`: start the isolated GNOME
session as an unprivileged dedicated test user, use `in-gnome-session.sh` for
clients, and `native-input.py` for Mutter RemoteDesktop native input. Set
`LINUXDROP_REVIEW_SIZE=610x760` (or another tested size) when launching the app.
`native-receive.py` trusts the dedicated daemon's public certificate and waits
for real consent; enable visibility for the test first. Keep test daemons on a
separate port or stop them before a live demo to avoid conflicting listeners.

Still open: physical Apple/Android interoperability, real WLAN/USB/BLE hardware,
125–200% fractional scaling, multi-monitor hotplug, GDM lock/unlock, file-portal
drops from sandboxed applications, accessibility screen-reader traversal, GNOME
versions other than 46, and system-theme portal propagation in a full desktop.
Explicit Light/Dark selection was verified; the isolated headless desktop does
not supply all normal desktop portal/session services.
