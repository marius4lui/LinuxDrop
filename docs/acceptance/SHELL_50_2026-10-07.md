# GNOME Shell 50 compatibility and actual drop-window geometry

The production metadata now lists GNOME 46 and 50. Both passed the existing
native Shell actor/settings scenario at German 150% text and an 800x600 virtual
monitor. Fedora 44 supplied GNOME Shell/Mutter 50.5 and GJS 1.88.1. The Ubuntu
regression used GNOME Shell 46.2. No 47/48/49/51 claim follows from this check.

GNOME 50 initially refused extension enable because `affectsInputRegion` was
removed from LayoutManager's accepted chrome options. The installed Shell 46
resource explicitly defaults this option to true; omitting it preserves that
behavior and allows Shell 50 to enable the extension. This was verified against
the actual `layout.js` resources in `libshell-14.so` and `libshell-18.so`.
See also the [upstream GNOME 50 porting guide](https://gjs.guide/extensions/upgrading/gnome-shell-50.html)
for the removal of X11 restart support and related release context.

The native preferences runner also needed distro-correct private library and
GI typelib directories. It now checks lib, lib64 and multiarch Shell locations,
which fixes Fedora's otherwise missing Shew namespace without changing product
preferences code.

## Actual installed GTK handoff

`LINUXDROP_SMOKE_REAL_DROP=1` optionally extends the existing smoke with an
actual installed `linuxdrop --notch-drop` process on the private Wayland display.
It exposed a second defect: centering assumed a 350-pixel width even when GTK's
natural width grew with text scaling. The Shell now positions from the measured
frame, listens for subsequent size changes, and applies the configured top
spacing while keeping the surface below the panel. It no longer forces GTK's
natural size to an assumed 350x180 rectangle.

On both Shell versions the native scenario verified two real launches, frame
centering, panel/screen bounds, replacement of the Shell bubble, pending-state
clearance, live top-offset changes, close and reopen. Existing consent, keyboard,
progress, stale-owner/reply, action recovery and preference assertions passed.

## Isolation and limits

The Fedora root uses private mount/PID/IPC/network namespaces, a private system
D-Bus, an unprivileged test user, and a private session bus/display/settings.
GNOME 50 needs the private system bus even for headless startup; its absence
initially stopped Shell before extension enable. No host radio/device mounts
were provided. Ubuntu uses the existing isolated native runner with fresh XDG
state and a private bus/display. The user's live demo was never changed.

Expected unavailable calendar/PipeWire/session services and shutdown messages
remain fixture noise. This acceptance does not prove native external file-drag
payload delivery on GNOME 50, booted user-session service/polkit lifecycle,
physical mixed-DPI or screen-reader speech. The GTK capture also shows that
fixed-pixel custom label typography scales differently from native buttons;
that remaining accessibility polish is recorded in UI_GAPS.md. The overall
completion goal therefore remains open.
